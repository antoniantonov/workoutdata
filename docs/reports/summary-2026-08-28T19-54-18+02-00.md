## 2. Confirmed Garmin data flow

Garmin is not imported directly into DuckDB or PostgreSQL.

The implemented flow is:

```text
Garmin Connect
  -> GarminDB / garth authentication and download
  -> GarminDB SQLite databases
  -> garmin_etl transformation layer
  -> DuckDB and/or PostgreSQL
```

The immediate ETL source is GarminDB SQLite:

| SQLite database | Source table | Imported content |
|---|---|---|
| `garmin_activities.db` | `activities` | One summary row per Garmin activity |
| `garmin_activities.db` | `activity_records` | Activity heart rate, GPS, and sensor records |
| `garmin.db` | `sleep` | Daily sleep summaries |

The destination tables are:

| Table | Key | Contents |
|---|---|---|
| `garmin_workout_metadata` | `activity_id` | Activity summary, `workoutId`, duration, distance, HR summary, and initial GPS coordinate |
| `garmin_timeseries` | `(activity_id, record)` | Per-record timestamp, HR, GPS, speed, distance, cadence, altitude, temperature, and GarminDB `rr` |
| `garmin_sleep` | `day` | Sleep window, sleep-stage durations, SpO2, respiration, stress, score, and qualifier |

DuckDB is stored at:

```text
jobs/import-garmin/local_data/garmin.duckdb
```

PostgreSQL data is stored at:

```text
jobs/import-garmin/local_data/postgres/
```

## 3. Docker Compose redesign

`jobs/import-garmin/docker-compose.yml` was expanded into purpose-specific
services.

| Service | Purpose |
|---|---|
| `garmin-auth` | Interactive Garmin login and MFA |
| `refresh-garmin-source` | Download and import Garmin data into GarminDB SQLite |
| `import-garmin-duckdb` | Transform the SQLite source and load DuckDB |
| `postgres` | Persistent PostgreSQL 17 service |
| `import-garmin-postgres` | Transform the same SQLite source and load PostgreSQL |
| `query-duckdb` | Run read-only SQL against DuckDB |
| `query-postgres` | Run read-only SQL against PostgreSQL |
| `validate-garmin` | Validate SQLite, DuckDB, and PostgreSQL equality and integrity |

### 3.1 Shared container paths

All importer and tool services use the same mounted `local_data` directory:

```text
/app/local_data/.GarminDb
/app/local_data/garmin_sqlite
/app/local_data/garmin_sqlite/DBs
/app/local_data/garmin.duckdb
```

The bind mount keeps GarminDB downloads, the Garmin session, DuckDB, and
PostgreSQL data outside disposable importer containers.

### 3.2 PostgreSQL service

The new Compose PostgreSQL service:

- uses `postgres:17.2-alpine`;
- persists data under `local_data/postgres/`;
- uses `pg_isready` for its health check;
- waits until healthy before PostgreSQL imports, queries, or validation run;
- exposes container port `5432` through host port `5433` by default;
- uses `POSTGRES_SSLMODE=disable` for the internal local Compose connection.

The importer, query, and validation services explicitly set:

```yaml
POSTGRES_CONNECTION_STRING: ""
POSTGRES_HOST: postgres
POSTGRES_PORT: "5432"
```

Clearing `POSTGRES_CONNECTION_STRING` prevents an existing `.env` value from
silently redirecting the self-contained local workflow to an external database.

### 3.3 Sequential source and destination processing

Live source refresh is now independent of destination loading:

```bash
docker compose run --rm refresh-garmin-source
docker compose run --rm import-garmin-duckdb
docker compose run --rm import-garmin-postgres
```

This contacts Garmin once, creates one SQLite snapshot, and loads both database
backends from that exact same source.

## 4. Dockerized Garmin authentication

Added:

```text
jobs/import-garmin/garmin_etl/auth.py
```

The authentication command is:

```bash
docker compose run --rm garmin-auth
```

The command:

1. Prompts for the Garmin email inside the container.
2. Prompts for the Garmin password with hidden input.
3. Allows `garth` to request an MFA code when required.
4. Creates the single-file `garth_session` format expected by
   `garmindb==3.7.0`.
5. Writes the token to:

   ```text
   local_data/.GarminDb/garth_session
   ```

6. Applies file permissions `0600`.

The password and MFA code are not written to `.env`, the image, or repository
files.

The obsolete host-side renewal helpers were removed:

```text
jobs/import-garmin/scripts/renew_garmin_token.py
jobs/import-garmin/scripts/renew_garmin_token.sh
```

The normal workflow no longer requires host Python, host `uv`, or locally
installed Garmin packages.

## 5. Garmin OAuth session-expiry correction

The initial download preflight treated this OAuth2 metadata field as definitive
session expiry:

```text
refresh_token_expires_at
```

The persisted session reported stale OAuth2 refresh metadata and was initially
blocked before GarminDB could attempt authentication.

Fleet research into `garth==0.6.3` established that this was not a reliable
whole-session expiry test. That version can exchange the longer-lived persisted
OAuth1 credential for new OAuth2 credentials.

The behavior in `garmin_etl/download.py` was changed from:

```text
OAuth2 refresh metadata expired -> abort
```

to:

```text
OAuth2 refresh metadata expired
  -> print a warning
  -> allow garth to attempt OAuth1-to-OAuth2 renewal
  -> let the live Garmin API call determine whether the session is valid
```

This allowed the existing OAuth1 session to authenticate and complete the live
Garmin refresh without requesting a new password or MFA code.

Authentication failure handling remains strict. GarminDB can return process
exit code zero after some authentication failures, so the wrapper also scans
combined output for markers including:

```text
Failed to login
Login failed
Authentication failed
Failed to authenticate
session expired
401 Client Error
403 Client Error
```

When a failure marker is detected, the refresh returns failure and instructs
the operator to run:

```bash
docker compose run --rm garmin-auth
```

## 6. Standalone Garmin source refresh

`garmin_etl/download.py` now has a command-line entry point used by:

```bash
docker compose run --rm refresh-garmin-source
```

The service:

- writes the generated GarminDB configuration under
  `local_data/.GarminDb/`;
- uses the token from that mounted directory;
- runs the GarminDB download/import command;
- captures and streams GarminDB output;
- checks process exit status;
- checks textual authentication-failure markers;
- exits nonzero when a required live refresh fails.

The database import services run with `GARMIN_DOWNLOAD=false`, ensuring that
DuckDB and PostgreSQL do not independently contact Garmin.

## 7. Read-only database query tooling

Added:

```text
jobs/import-garmin/garmin_etl/query.py
```

Example commands:

```bash
docker compose run --rm query-duckdb \
  --sql "SELECT COUNT(*) FROM garmin_workout_metadata"

docker compose run --rm query-postgres \
  --sql "SELECT COUNT(*) FROM garmin_workout_metadata"
```

The query client:

- uses the job's normal environment configuration;
- supports DuckDB and PostgreSQL;
- prints tabular query results;
- accepts SQL through `--sql` or standard input;
- returns a nonzero exit code when SQL fails;
- opens DuckDB with `read_only=True`;
- sets PostgreSQL connections to read-only mode.

The PostgreSQL read-only setting was added after final code review found that a
write statement would otherwise appear to succeed but be rolled back when the
connection closed. Both query backends now reject writes consistently.

## 8. Exact source and backend validation

Added:

```text
jobs/import-garmin/garmin_etl/validate.py
```

Run:

```bash
docker compose run --rm validate-garmin
```

The validator:

1. Transforms the current GarminDB SQLite source.
2. Reads every destination table from DuckDB.
3. Reads every destination table from PostgreSQL.
4. Normalizes nullable values and date/time representations.
5. Compares every row and value with the transformed source.
6. Compares DuckDB and PostgreSQL with each other.

Integrity checks include:

- primary-key uniqueness;
- non-null `activity_id`;
- non-null and unique workout metadata `workoutId`;
- valid `gps_source` values:
  - `first_record`
  - `activity_start`
  - `none`
- no orphan timeseries rows;
- matching `activity_id` relationships;
- matching timeseries and metadata `workoutId`;
- non-null sleep primary-key dates.

The comparison uses stable table column contracts from `garmin_etl.transform`
and checks actual row values rather than relying only on aggregate counts.
